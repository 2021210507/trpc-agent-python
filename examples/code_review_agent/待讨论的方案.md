# 待讨论的方案：Tree-sitter 用于 patch-only 审查

## 1. 状态

- 状态：待 D4 评测后决定
- 当前结论：本期不引入 Tree-sitter，不修改标准库 AST 主路径
- 适用范围：只有 unified diff 或 PR patch、无法读取变更后完整文件的输入
- 规范关系：本文是非规范性决策记录；与 `DEV_SPEC.md` 冲突时以 `DEV_SPEC.md` 为准

## 2. 待决定的问题

当前 `--repo-path` 会先通过 `git diff HEAD` 获得文件路径和变更行号，再读取工作区中的
完整新文件。语法有效时使用 `ast.parse()`，并将 AST 节点范围与 `new_changed_lines`
相交，只报告当前变更。`--files` 同样有完整文件，但采用 `full_file` 全量扫描语义。

纯 `--diff-file` 或只有 PR patch 的输入通常拿不到修改后的完整文件。修改文件保持
`full_text=None`、`analysis_mode=diff_heuristic`，完整文件 AST 规则跳过，只运行新侧行级
规则。需要讨论的是：是否为这一受限输入增加 Tree-sitter fragment fallback。

## 3. 当前实验依据

候选依赖基准使用仓库 `.venv`，重新运行 7 轮。每轮使用全新临时目录和固定种子乱序语料，
覆盖 24 个完整 Python 样本、20 个残缺片段和 82 个安全正负样本，共 126 个唯一样本、
882 次样本执行。

| 解析器 | 完整代码 | 残缺片段保留结构 | 热解析中位数 | 包体 |
|---|---:|---:|---:|---:|
| 标准库 AST | 24/24 | 0/20 | 5.48 ms | 0 MiB |
| LibCST 1.8.6 | 24/24 | 0/20 | 67.61 ms | 约 11.49 MiB |
| Tree-sitter 0.26.0 + Python grammar 0.25.0 | 24/24 | 20/20 | 11.26 ms | 约 0.71 MiB |

该结果只证明 Tree-sitter 能从残缺文本中保留语法结构，没有证明它能提高真实 finding 的
Recall 或降低误报。patch 仍可能缺失 import、别名、变量定义、调用上下文和跨行数据流；
“能够解析”不能直接等同于“能够高置信判定风险”。

## 4. 当前方案

```text
完整文件可得
  → 标准库 ast.parse()
  → AST 节点与 changed lines 相交

只有 patch
  → diff parser 保留 hunk 与真实行号
  → 行级确定性规则和 secret 检测
  → 依赖完整上下文的规则跳过或进入人工复核
  → 报告标明 analysis_mode=diff_heuristic
```

PR 审查环境若能够 checkout PR Head，应优先读取完整文件，而不是把 PR patch 当成唯一输入。

## 5. D4 决策门槛

只有同时满足以下条件，才考虑引入 Tree-sitter：

1. 建立独立的 patch-only 正例、负例和残缺语法观测集；
2. 当前 patch-only 高危 Recall 低于 `0.80`；
3. 失败归因表明主要漏检来自无法构造 AST，而不是缺失语义或规则覆盖不足；
4. Tree-sitter fallback 使 Recall 至少提高 `0.10`；
5. finding-level 误报占比不超过 `0.15`；
6. 总评审耗时仍不超过 120 秒，并满足单次/累计沙箱预算；
7. `tree-sitter`、语言 grammar、Python 版本和镜像哈希能够固定，宿主与 Container 版本一致；
8. 评审运行期间保持 `network_policy=deny`，不得临时安装或下载 grammar。

未达到门槛时继续使用标准库 AST，不因解析成功率单一指标增加生产依赖。

## 6. 若批准后的实现边界

Tree-sitter 只能作为 `full_text` 不可得或标准库 AST 解析失败时的 fallback，不替换完整文件
AST。查询必须注册为确定性规则，输出仍走现有 `RuleMatch`、changed-line 过滤、去重、分桶、
脱敏和报告链路。缺少 import、别名或数据流证据的结果不得进入高置信 findings，只能进入
`needs_human_review` 或保持为声明盲区。

引入前必须同步更新 `DEV_SPEC.md`、固定依赖声明、受控 Container 镜像、Skill manifest
摘要、规则文档、D4 语料和回归测试。不得把宿主 `.venv` 可导入当作沙箱可用证据。

## 7. 与规则覆盖增强的关系

当前实验暴露的首要问题是危险 API 和 SQL 构造变体覆盖不足，不是标准库 AST 的性能。
因此先扩展能够由完整 AST 确定的规则，并将需要变量传播的模式继续列为盲区。完成 D4
归因前，不使用 Tree-sitter 掩盖规则本身缺失的问题。

规则回补后使用同一份 82 个安全样本重新运行 7 轮：核心正例保持 `30/30`，变体正例从
`1/12` 提升到 `10/12`，30 个负例仍为 0 误报，且每轮结果一致。剩余两项分别是
`evaluate = eval` 的运行时函数别名和 `shell=use_shell` 的变量传播；它们需要数据流证据，
不应为了提高表面 Recall 直接进入 0.92 置信度 AST findings。该结果进一步支持“先完善
规则与 D4 归因，再决定 Tree-sitter”的当前结论。
